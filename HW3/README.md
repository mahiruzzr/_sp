# 多執行緒並行程式設計與同步機制指南 (Multi-Threading & Concurrency Guide)

本文件深入解析作業系統與多執行緒程式設計中的核心概念（Thread、Race Condition、Mutex、Deadlock），並透過三個經典的 C++ 實戰範例（銀行存提款、生產者-消費者、哲學家用餐），詳細展示如何處理並行運算（Concurrency）中的資料同步與死結預防問題。

---

## 核心概念解析

在多核心處理器普及的現代，為了提升程式的執行效率，多執行緒程式設計（Multi-Threading）已成為必備技能。然而，共享記憶體的架構也帶來了資料不一致與資源死鎖的風險。

### 1. 執行緒 (Thread)
* **定義**：執行緒是作業系統能夠進行運算排程的最小單位。它被包含在行程（Process）之中，是行程中的實際運作單位。
* **特性**：同一行程內的多個執行緒會**共享該行程的記憶體空間**（如全域變數、堆積空間 Heap），但每個執行緒擁有自己獨立的**程式計數器（PC）**、**暫存器集合**與**堆疊空間（Stack）**。
* **優缺點**：
    * *優點*：執行緒間切換（Context Switch）的成本遠低於行程切換；共享記憶體使資料交換極為流暢。
    * *缺點*：由於共享資源，若缺乏適當的同步機制，極易引發資料損毀與邏輯錯誤。

### 2. 競態條件 (Race Condition)
* **定義**：當兩個或多個執行緒同時存取同一個共享資料，且至少有一個執行緒在進行「寫入」操作時，最終的執行結果取決於這些執行緒執行的相對順序（或稱排程隨機性）。這種現象稱為競態條件。
* **發生原因（非原子操作）**：高階語言的一行代碼（如 `balance += 100`），在 CPU 層級實際上會被拆解為三個指令：
    1. **Read**：將記憶體中的變數值讀取到 CPU 暫存器中。
    2. **Modify**：在暫存器中將該值加上 100。
    3. **Write**：將暫存器中的新值寫回記憶體。
    當多個執行緒交錯執行這三個步驟時，舊的值就會覆蓋掉其他執行緒剛寫入的新值，導致更新遺失。

### 3. 互斥鎖 (Mutex)
* **定義**：互斥鎖（Mutual Exclusion Lock）是一種用來控制多個執行緒存取共享資源的同步機制。
* **運作原理**：互斥鎖保證在任何給定時間內，**只有一個執行緒**能夠持有該鎖並進入「關鍵區段（Critical Section）」。其他試圖獲取該鎖的執行緒將會被阻塞（Block）或掛起，直到持有鎖的執行緒釋放它。
* **最佳實踐**：在 Modern C++ 中，不建議手動呼叫 `mtx.lock()` 和 `mtx.unlock()`，因為若關鍵區段內發生異常或提前 `return`，會造成死鎖。應使用 RAII 機制（如 `std::lock_guard` 或 `std::unique_lock`）來自動管理鎖的生命週期。

### 4. 死結 (Deadlock)
* **定義**：死結是指兩個或多個執行緒在執行過程中，因爭奪資源而造成的一種**互相等待**的僵持狀態。若無外力介入，這些執行緒將永遠無法繼續執行。
* **死結發生的四個必要條件（Coffman Conditions）**：
    1. **互斥 (Mutual Exclusion)**：資源一次只能被一個執行緒使用。
    2. **持有並等待 (Hold and Wait)**：執行緒已保持至少一個資源，但又提出了新的資源請求，而該資源已被其他執行緒佔有，此時請求執行緒阻塞，但對自己已獲得的資源保持不放。
    3. **不可剝奪 (No Preemption)**：執行緒已獲得的資源在未使用完之前，不能被其他執行緒強行奪走。
    4. **循環等待 (Circular Wait)**：存在一個執行緒的資源等待鏈，例如：Thread A 等待 Thread B 的資源，Thread B 等待 Thread C 的資源，Thread C 又等待 Thread A 的資源。
